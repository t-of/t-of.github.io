# スタジオの引っ越し資料

T.OF... スタジオ（`npm run studio` → http://localhost:4141）を大きく作り直すときに渡す資料。
何のデータをどこから読み、何を画面に出し、何を守らないといけないかをまとめる。
コードを読まなくても作り直しの依頼が書けることを目指す。

コード（`studio/server.mjs`・`app.js`・`style.css`）を変えたら、この資料も合わせて直す。

---

## この資料を受け取った AI へ

オーナーが「こんなデザイン・動きにしたい」と言ったら、**実装を担当する AI に渡すプロンプト**を 1 本書いて返す。自分で作り始めない。

プロンプトには次を入れる。

1. **目的**: オーナーの要望を、画面・動きの言葉に言い換えたもの。あいまいな所（色・速さ・どの画面か）は、下の「今の画面」に合わせて具体的にする。決めきれない所は、プロンプトの前にオーナーに 1〜3 個だけ聞く。
2. **変える範囲**: どのファイル・どの画面・どの部品か。変えないもの（API・データの形・ほかの画面）もはっきり書く。
3. **使うデータ**: 下の「データ」「API」から、その画面に要る項目だけを抜き出して、形ごと書く（例の JSON も付ける）。
4. **守ること**: 下の「守ること」から関係するものを全部。特に動きには `prefers-reduced-motion` の代わりの見せ方を必ず書く。
5. **終わりの条件**: どうなっていれば完成か。スマホ幅（390px）とパソコン幅（1280px）で崩れない、ライブの更新で壊れない、など確かめ方も。

書き方: 日本語。見出しと箇条書き。オーナーの言葉は引用で残す。プロンプトは 1 つのコードブロックに入れ、そのまま貼れるようにする。

## これは何か

- T.OF...（個人の制作レーベル）の「社内の様子」を見るダッシュボード。社員はすべて AI（Claude Code のサブエージェント）。
- オーナーは Claude Code（ターミナル）で**ディレクター**と話す。ディレクターが仕事を係（メンバー）に振る。スタジオはその様子を**見る**ための画面で、会話はしない。
- 動いている間の雰囲気は「小さな会社のオフィス」。部屋（係）ごとに席があり、仕事が来ると書類が部屋から部屋へ飛ぶ。
- オーナーが自分の番（選ぶ・決める）に気づけることが一番大事。次に、今だれが何をしているかが一目で分かること。

## 構成

| ファイル | 役目 |
|---|---|
| `studio/server.mjs` | Node の標準だけで書いたサーバー（依存なし）。記録を読んで状態を作り、SSE で画面に送る。127.0.0.1:4141 |
| `studio/index.html` / `app.js` / `style.css` | 画面。フレームワークなし、素の JS（ES module）と CSS。ビルドなし |
| `studio/office.js` | 社内タブの中身（ドット絵のバーチャルオフィス）を SVG で描くだけのモジュール。`app.js` が `import` して使う。自分では SSE をつながない（`officeAgents`/`officeBoard`/`officeLog` を app.js の SSE ハンドラから呼ぶ） |
| `studio/trademark.html` / `trademark.js` | 商標チェック（別ページ。オーナーが手で引いた結果を記録する） |

- 読み込むフォントは Google Fonts の Space Grotesk だけ。ロゴ・アイコンは `/hub/...` で本部から借りる。
- 画面は受け取った状態を描くだけ。状態を作るのはサーバー。

## 係（ROLES）

`app.js` の `ROLES`。色とアイコンは部屋・フィード・グラフで使う。

| キー | 係 | リーダー | 色 | アイコン |
|---|---|---|---|---|
| director | ディレクター（会話・割り振り） | 佐藤 | #ffd35c | ◆ |
| researcher | リサーチ（調査・アイデア） | 山本 | #5b8cff | ⌕ |
| planner | 企画（仕様・名前） | 佐々木 | #9d7bff | ✎ |
| designer | デザイン（アイコン・画像） | 清水 | #e24bc6 | ✦ |
| engineer | 実装（コード） | 石川 | #2cc6e0 | ⌘ |
| qa | 品質（チェック・確認） | 村上 | #36a075 | ✓ |
| release | リリース（公開・掲載） | 藤井 | #e2582e | ↑ |
| writer | note（記事の下書き） | 岡本 | #41c9b4 | ✍ |
| owner | オーナー（あなた） | — | #eceef3 | ★ |

- 同じ係の人が何人も同時に動く。席に着いた人には `PEOPLE`（係ごとに 6〜12 人の名前）から、重ならない名前を付ける。先頭がリーダー。
- 成績は一人ずつではなく係（チーム）ごとに出す（DECISIONS.md「スタジオの係の名前」）。
- 上の `ROLES`/`PEOPLE`（日本の名字、漢字。係ごと 6 人、重ならない 48 個）は `studio/office.js` が持つ 1 か所だけの名簿。`app.js` は `import { ROLES, leader, nameOf } from './office.js'` して使うので、フロアの札も `#feed`・成績・プロジェクトの詳細も同じ名前になる。id → 名前は `nameOf(role, id)`（id から決まる、常に同じ）で決める。

## データ

### 1. 作業記録（読むだけ）

`~/.claude/projects/-Users-<名前>-GitHub*/<session>.jsonl` と `<session>/subagents/agent-<id>.jsonl`（＋ `.meta.json`）。Claude Code が書く。**スタジオは絶対に書き込まない。**
サーバーはファイルごとに読んだ位置を覚えて、増えた分だけ読む。直近 12 時間に更新されたものだけ見る。

ここから作る状態（`agents` イベントで送る。1 要素 = 1 会話）:

```json
{
  "id": "4d1274bd-…", "title": "ペントリスの不具合を直す", "cwd": "~/GitHub/tof/t-of.github.io",
  "lastAt": 1790233982605, "state": "working",
  "action": "依頼: Fix pentris", "lastText": "直しました。…", "apps": ["pentris"],
  "agents": [
    { "id": "a379f87bc1be349f1", "type": "engineer", "role": "engineer", "description": "Fix pentris",
      "startedAt": 1790231115458, "lastAt": 1790231260136, "tools": 15,
      "state": "done", "action": "完了", "lastText": "…", "apps": ["pentris"] }
  ],
  "log": [ { "at": 1790231115458, "agent": null, "role": "director", "text": "依頼: Fix pentris", "to": "engineer", "kind": "handoff" } ]
}
```

- 会話の `state`: `working` / `idle`（3 分記録なし）。エージェントの `state`: `working` / `stalled`（3 分記録なし＝止まっているかも）/ `done`。
- `action` は道具の呼び出しを一言にしたもの（「読む: pentris/app.js」「コマンド: チェックを実行」など）。
- `role` は `type` から、なければ依頼文から推測する。
- `apps` は書き込んだ先のファイルと依頼文から拾ったアプリの id。
- `log` の `kind`: `handoff`（ディレクター → 係に依頼）/ `return`（差し戻し。依頼の説明に「直す・修正」など）/ `report`（係 → ディレクターに完了報告）/ なし（ただの動き）。

### 2. ボード `docs/board.json`（読み書き）

プロジェクトとタスク。ディレクターが `tools/board.mjs` で書き、オーナーはスタジオの画面から書く。
`docs/board-archive.json`（終わったタスクの過去分）も読んで合わせて出すが、保存するときはアーカイブ済みのものを除く。

```json
{
  "about": "…", "updatedAt": "2026-09-26T10:00:00.000Z",
  "projects": [ { "id": "dot-rush", "name": "DOT RUSH", "stage": "build", "created": "2026-09-25", "note": "最初の版" } ],
  "tasks": [
    { "id": "t12", "project": "dot-rush", "title": "タイトル画面を作る", "owner": "engineer",
      "status": "doing", "created": "2026-09-25", "doneAt": null },
    { "id": "t13", "project": "dot-rush", "title": "アイコンの案を選ぶ", "owner": "owner", "status": "waiting",
      "created": "2026-09-25", "doneAt": null,
      "choices": ["A", "B"], "choiceLabels": { "A": "丸", "B": "角" },
      "choiceImages": { "A": ".audit/a.svg", "B": ".audit/b.svg" }, "images": [".audit/sheet.png"],
      "choice": null, "comment": null }
  ],
  "ideas": []
}
```

- `stage`: idea → planning → design → build → qa → release → live
- `status`: todo（未着手）/ doing（進行中）/ waiting（待ち）/ done（完了）/ skip（しなくていい）。done・skip は `doneAt` に日付。
- `owner` は係のキー。`owner: "owner"` で閉じていないものが「あなたの番」。
- `choices` があるタスクは、オーナーが画面で選ぶ（`choice` と `comment` が入り done になる）。画像は `/hub/<パス>` で出す。
- 数は 300 件をこえる。

## API

| 道 | 内容 |
|---|---|
| `GET /api/events` | SSE。つないだ直後に `agents`・`board`・`audit` を 1 回ずつ送り、そのあと変わるたびに送る |
| `GET /api/apps` | apps.js の中身 |
| `GET /api/ledger` | 台帳の全行 |
| `GET /api/board` / `PUT /api/board` | ボード全体を読む・書く（`projects` と `tasks` が配列でないと 400） |
| `POST /api/audit?browser=1` | チェックを走らせる（結果は `audit` イベントで届く） |
| `GET /api/trademark` / `PUT /api/trademark/result` | 商標の読み・1 件書き（`{key, status, note}`） |
| `GET /shots/<名前>` | `.audit/` の画像 |
| `GET /hub/<パス>` | 本部のファイル（ロゴ・アイコン・案の画像） |

SSE のイベント: `agents`（上の配列）/ `board`（ボード全体）/ `audit`（要約、または `{running:true}`）/ `apps`（公開したとき）/ `ledger`（1 件増えた）/ `log`（1 件の動き。`{session, at, agent, role, text, to?, kind?}`）。

サーバーが勝手にやること: board.json が変わったら Finder のフォルダの色を付け直し、「あなたの番」が増えたら mac に通知（音つき）。apps.js が変わったらチェックをやり直す。

## 今の画面

ヘッダー（上に固定）: ロゴ＋「STUDIO」、タブ（社内・プロジェクト・タスク・成績）、「商標チェック」、**「★ あなたの番 N」**、接続の点（ライブ／再接続中）。その下に数字の列（作業中のメンバー、動いている会話、作っているアプリ、未完了のタスク、あなたの番、チェック不合格のアプリ）。

| タブ | 中身 |
|---|---|
| 社内 | **ドット絵のバーチャルオフィス**（`office.js` が 1 枚の SVG で描く）。上から見下ろした間取りで、係ごとの部屋（見出し・ホワイトボード・机）、オーナー室（あなたの番の書類の山）、休憩所（終わった人がソファでひと息）、廊下と入口がある。人はドットの見た目で、席・休憩所・入口の間を歩いて移動する（クリックで名前・仕事・経過時間のカードが出る）。画面の幅に合わせて横長／縦長の 2 通りの間取りに切り替わる。右に「今日の日報」（完了タスク・延べ人数・依頼・報告・差し戻し、係ごとの帯グラフ）と「いまの動き」（フィード。最新 60 件） |
| プロジェクト | 段階ごとの列（かんばん）にアプリのカード。動いているものは光る。押すとシート（段階・メモの編集、作業中のメンバー、タスク、チェック結果）。「＋ 新しいプロジェクト」「チェックを実行」 |
| タスク | 追加フォーム（題・プロジェクト・係）、絞り込み（未完了・あなたの番・完了/不要・すべて）、プロジェクトごとのまとまり。行ごとに完了のチェック、状態の切り替え、削除、画像（押すと拡大）、**案のカード**（choices。押して選ぶ、ひとことを添える） |
| 成績 | 期間（今週・今月・すべて）。今月の MVP、係ごとのカード（レベルと次までの帯、バッジ）、表（係・モデル・件数・平均時間・平均トークン・一発合格率）、差し戻しの一覧、案の採用 |

レベル: 係の累計件数 n から Lv = ⌊√n⌋ + 1。バッジ: 初仕事・ベテラン（50 件）・100 件・一発合格 10 連続・省エネ・夜ふかし。

### 今の動き

| 名前 | いつ | どう動く |
|---|---|---|
| 人が歩く | 席に着く／離れる、書類を届ける、休憩所へ移動するとき | ドットの人が部屋・廊下・入口をつなぐ道すじを rAF で歩く。足踏み・腕振りのコマ送り付き |
| 書類を届ける（office.js の `deliver`） | `log` に `kind` が来たとき（最初の読み込みでは飛ばさない） | ディレクター役の人が係の部屋へ（依頼・差し戻し）／係の人がディレクターへ（報告）歩いて書類を渡す。着いたらその場所が光る（flash） |
| あなたの番が揺れる（wiggle） | あなたの番が増えたとき | ヘッダーの「★ あなたの番」ボタンが ±6° を 0.4 秒 × 3 回（app.js 側。社内タブ固有ではない） |
| 打つしぐさ（is-type） | 自分の席で working の間 | 腕が小刻みに動く |
| 画面がちらつく（screen.is-on） | working の人のモニター | 1.3 秒で明滅 |
| オーナー室が光る（owner-glow） | あなたの番が 1 件以上のとき | 2 秒で繰り返す |
| カードが光る（glow） | 作業中のメンバーがいるプロジェクト（プロジェクトタブ） | 1.8 秒で繰り返す |
| 接続の点（ping） | ライブの間 | 緑の輪が広がる、2 秒 |

`prefers-reduced-motion: reduce` のときは歩く・打つ・ちらつく・光るを止め、人はすぐ目的の場所（席・休憩所）に瞬間移動し、書類は届いた場所が光るだけになる（office.js の `reduceMotion()` と、style.css の対応する `@media` の両方で止めている）。

## 守ること

- **外に公開しない**。127.0.0.1 だけで待ち受ける。外部のサービスに記録を送らない。
- **作業記録には書き込まない**（Claude Code のもの）。
- **board.json はオーナーとディレクターが同時に触る**。画面から書くときは、今の中身を読んでから全体を PUT する今のやり方を崩さない。JSON を壊さない。アーカイブ済みのタスクを board.json に戻さない。
- データの形（board.json・ledger.jsonl・API・SSE）を変えるなら、`tools/board.mjs`・`CLAUDE.md` の「ボード」も合わせて直す。変えずに済むなら変えない。
- 依存を足さない（サーバーは Node の標準だけ、画面はビルドなし）。足すなら理由を DECISIONS.md に書く。
- `prefers-reduced-motion` の代わりの見せ方を必ず用意する。色だけで意味を伝えない（文字かアイコンも添える）。
- 390px の幅でも使える（はみ出さない、押せる大きさ 44px 以上）。
- 書類・レベルアップなどの演出は、**届いた新しいできごと**にだけ出す。最初の読み込みや再接続で一斉に出さない。
- 何十人も同時に動いても重くならない（今は 1 秒ごとに作業記録を読み、変わったときだけ送る）。
- 「あなたの番」がいつも一番目立つ。演出がそれを隠さない。

## これから（VISION.md より）

- T.OF... をいくつもの部署がある組織にする。今の係は「アプリ開発部」で、横に「note 運用部」「SNS 運用部」などが並ぶ。**スタジオにも部署ごとに出す**。
- 今のボードとスタジオはアプリ開発の段階（企画 → 公開）が前提。部署を足すときは、部署ごとの仕事を載せられる形に作り直す。
