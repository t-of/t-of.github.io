# 新しいアプリを作る

ディレクターとして、次の順に進める。各段階の終わりでオーナーに短く報告する。

## 1. 企画（planner）

- オーナーのアイデアを `planner` に渡し、`docs/specs/<id>.md` を作らせる。
- 仕様の要点と「決めてほしいこと」（名前の候補など）をオーナーに見せ、**名前と内容の OK をもらう**。

## 2. デザインと実装（並行）

- `engineer` に: `tools/new-app.sh` でひな形を作り、仕様どおりに本体を書く。終わりの条件は `npm run audit:browser -- <id>` の合格（アイコン関係を除く）と、アプリのテスト。コミットはしてよい、push はしない。
- `designer` に: アイコン一式と共有画像を作る。触るのは `icons/` だけ。
- 2 人が同じファイルを触らないように、ひな形ができてから designer を始める。

## 3. 品質（qa）

- `qa` に全体を確かめさせる。問題があれば `engineer` か `designer` に戻して直させ、もう一度 `qa`。
- 合格したら、スクリーンショットと遊び方の要約をオーナーに見せ、**公開の OK をもらう**。

## 4. リリース（release）

- `release` に: 「オーナーの OK が出た」と伝え、`docs/RELEASE.md` の手順で公開させる（GitHub、Pages、About、apps.js、共有画像、本番の確認）。
- 公開した URL をオーナーに伝える。docs/BACKLOG.md のアイデア欄から消す。
