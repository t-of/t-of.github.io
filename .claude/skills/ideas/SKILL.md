# アイデアを探す

ディレクターとして、次の順に進める。テーマがあれば（例: /ideas 数字のパズル）その中で探す。

## 0. ボードに載せる

- docs/board.json の tasks に「アイデアを探す（<テーマ>）」を足す（`owner: "researcher"`、`status: "doing"`）。

## 1. 調べる（researcher を並行で 3 人）

切り口を分けて、`researcher` を 3 人同時に動かす。1 人 3 枚ずつカードを書かせる。

- **課金**: 課金・売上のランキングで上にいるジャンルや、有料版・サブスクが売れているツールやアプリ。小さく作れて同じ価値を出せるもの
- **利用の多さ**: 毎日開かれる・長く使われる（広告が効く）ゲームやツール。利用時間やリテンションが高いジャンル
- **需要**: よく検索されているのに良いものが少ない、困りごとを解く道具や遊び。紹介料（アフィリエイト）につながる計算・比較・診断のツールも探す

形は問わない（ゲーム、Web ツール、実用アプリ）。

頼むときは、切り口、テーマ、枚数、「書くのは docs/private/ideas/ だけ」を伝える。

## 2. 絞る（ディレクター）

- 全部のカードを読み、重なっているものをまとめる。
- 出典のないもの、稼げる根拠のないもの、大きすぎて最初の版が作れないものは落とす。
- **稼げるか**（課金、広告が効く使われ方、紹介料、検索から人が来る、品を売る など。researcher.md の「稼げるか」）を一番重く見て、根拠の確かさと合わせて上位 5 つに絞る。

## 3. オーナーに選んでもらう

- 5 つを docs/board.json の projects に足す（`stage: "idea"`、`note` にひとこと、`idea` にカードのパス）。スタジオのプロジェクト画面の「アイデア」列に出る。
- オーナーのタスクを足す: `owner: "owner"`・`status: "waiting"`、`choices` は 5 つの名前と「今回は作らない」、`choiceLabels` にひとこと。
  2 つ以上作りたいときはコメントに書いてもらう（例: 「B も」）。
- チャットにも 5 つを 1 行ずつ（名前、ひとこと、お金の取り方、稼げる根拠の要点）見せる。
- `node tools/wait-choice.mjs <task id>` をバックグラウンドで動かして、選ばれるのを待つ。

## 4. 選ばれたら

- 選ばれたものは `/new-app` の「1. 企画」から進める。planner にはカードのパスを渡し、カードの根拠と名前案を元に仕様を書かせる。
- 選ばれなかったものは projects から消す。カードは消さずに残す（次に調べるときの重なりの確認に使う）。
- 「アイデアを探す」のタスクを `done` にする。
